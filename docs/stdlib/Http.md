# Http

Generated by `plum doc` from the source. Do not edit by hand.

## `struct Header`

One header. `name` is as it appeared on the wire; header names are
case-insensitive in HTTP, so compare with care.

## `struct Response`

A complete response: status, headers, and the whole body.

## `struct Head`

A response's head, before the body has been read.

`leftover_body` is whatever arrived in the same read as the headers
— a body does not begin on a tidy packet boundary, so those bytes
have to be handed on rather than dropped.

## `struct Request`

An incoming request, as a handler receives it.

## `struct RequestLine`

A request's first line, split.

## `struct RequestHead`

A request's head, before its body has been read. `leftover_body`
carries the bytes that arrived alongside the headers.

## `let request (method: String) (url: String) (headers: Array[Header]) (body: String): Result[Response, String]`

Sends a request over HTTP or HTTPS. HTTPS verifies the peer's
certificate and hostname using the native TLS trust-store integration.

Invalid URL text, methods, header names, and header values return Err
before connecting. Methods and names must be nonempty ASCII tokens;
values may contain spaces, HTAB, and UTF-8, but no other ASCII controls
or DEL. Bodies are not subject to protocol-field validation.

Reads past up to 100 informational responses to the final response.
HEAD, 204, and 304 responses have an empty body regardless of framing
headers. Protocol upgrades (101) and successful CONNECT tunnels return
Err and close the connection; this API cannot hand off a transport.

## `let get (url: String): Result[Response, String]`

Fetches a URL and reads the whole response.

Supports both `http://` and `https://`; HTTPS uses the native TLS
transport with platform trust-store and hostname verification.

Redirects are NOT followed: a 301 or 302 comes back as itself, with
its `Location` header, so the caller decides. Following one changes
which host you are talking to, which is not a decision a library
should make quietly.

## `let post (url: String) (body: String): Result[Response, String]`

POSTs a body and reads the whole response. Sets `Content-Length`;
set `Content-Type` yourself if the server needs one.

Redirects are not followed — see `Http.get`.

## `let serve_once (port: Int) (handler: (Request) -> Response): Result[Unit, String]`

Handles exactly ONE connection then returns — listens, accepts once,
closes both the connection and the listening socket, and gives back
whatever `http_handle_connection` produced. Invalid handler headers
return Err without writing response bytes; the connection is closed.
Status codes must be 200..599: informational-only handler responses and
successful CONNECT tunnels return Err without writing response bytes.
HEAD, 204, and 304 suppress the handler's body. HEAD reports its byte
length; 204 and 304 omit Content-Length. Caller Content-Length and
Transfer-Encoding fields are replaced by this generated framing.
Malformed request lines/fields and missing (HTTP/1.1), duplicate, or
invalid Host fields receive 400 before body reading or handler dispatch,
then return Err. HTTP/1.0 may omit Host. Present Host values use URI host
syntax, including empty values, IP literals, and optional decimal ports.
Real, useful on its own
(a one-shot server, or a test fixture — this is what THIS module's
own tests exercise directly), not just a building block for `http_
serve` below.

## `let serve (port: Int) (handler: (Request) -> Response): Result[Unit, String]`

Serves HTTP on a port, calling `handler` once per request, forever.

**Never returns** unless listening or accepting fails. Connections
run concurrently. Invalid handler headers close that connection without
sending a response; other connections continue to be served. Invalid
request heads receive 400 and close, as described by `serve_once`.
