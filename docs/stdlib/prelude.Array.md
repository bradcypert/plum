<a id="Array.slice"></a>

## `let Array.slice (xs: Array[T]) (start: Int) (end: Int): Array[T]`

The elements from `start` up to but NOT including `end`.

Out-of-range bounds are clamped rather than an error, and a `start`
past `end` gives an empty array — so slicing near the end of an
array needs no arithmetic to stay safe.

fails; TRUE for an empty array, which is the convention everywhere

<a id="Array.join"></a>

## `let Array.join (parts: Array[String]) (sep: String): String`

Joins parts in order with `sep` between adjacent entries. Empty parts
still contribute separator boundaries.

Copies parts and separators directly into one exact-sized allocation.
Empty output uses shared static storage.

<a id="Array.sort_by"></a>

## `let Array.sort_by (arr: Array[T]) (le: (T, T) -> Bool): Array[T]`

Sorted by a \"less than or equal\" predicate.

STABLE: elements `le` considers equivalent keep their original
order, which is what makes sorting by one key and then another
produce the ordering people expect.

Merge sort with O(n log n) comparisons and O(n) auxiliary storage.

## `let Array.sort_float (arr: Array[Float]): Array[Float]`

<a id="Array.concat_all"></a>

## `let Array.concat_all (parts: Array[String]): String`

Concatenates parts in order, without a separator. The compiler's own
emitter uses this for collected output fragments.

Uses checked sizes and one exact-sized allocation for nonempty output;
empty output uses shared static storage.

<a id="Array.sort_string"></a>

## `let Array.sort_string (arr: Array[String]): Array[String]`

Sorted by BYTE order, not by any locale's alphabet — so uppercase
sorts before lowercase, and accented letters sort after `z`.

## `let Array.map (self: Array[T]) (f: (T) -> U): Array[U]`

A new array holding `f` applied to each element, in order. The result's element type is whatever `f` returns, so mapping can change it.

Implemented by the compiler itself, so it has no Plum source to read.

<a id="Array.push"></a>

## `let Array.push (self: Array[T]) (x: T): Array[T]`

A new array with `x` added at the end. The receiver is unchanged, but when it is dying the compiler reuses its cell rather than copying, so `acc = acc.push(x)` in a loop does not go quadratic.

Implemented by the compiler itself, so it has no Plum source to read.
